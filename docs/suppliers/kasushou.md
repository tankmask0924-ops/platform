# 卡速售 2.0 对接说明

> 依据文档：卡速售 2.0 API 接口文档（2026-09-11 整理版）
> 适用业务线：话费、卡券（卡速售不做电影票）
> 对接驱动：卡速售 2.0。卡速售是一套 SaaS 系统，不同站点接口相同，接入同系统的其他供应商只需新增供应商配置。

## 1. 核对结果

| 核对项 | 文档结论 | 对平台的影响 |
|---|---|---|
| 接口地址 | 每个站点域名不同，路径统一为 `/api/v1/...`，全部 POST + JSON | 供应商配置里填接口地址 |
| 测试环境 | 文档未提供 | 需向供应商确认 |
| 签名 | Header 传 `Sign`、`Timestamp`（13 位毫秒）、`UserId`（appid）；`Sign = sha1(Timestamp + 按参数名排序后的 JSON 请求体 + apikey)` | JSON 编码必须与对方一致：PHP `json_encode` 使用 `JSON_UNESCAPED_SLASHES \| JSON_UNESCAPED_UNICODE`，只对顶层参数排序；空请求体用 `{}`。文档中下单接口的签名示例少了引号，以 PHP 示例代码为准 |
| IP 白名单、频率限制 | 文档未说明 | 需向供应商确认 |
| 返回格式 | `{code, msg, data}`；code 只有 200 成功、400 失败（msg 为原因）、500 未知错误 | **没有细分错误码**，见第 3 节 |
| 下单 | 异步：返回受理结果（平台订单号 `ordersn`、状态），不代表充值成功；不返回卡密 | 下单后靠回调和查询拿最终结果 |
| 防重复 | `external_orderno` 传唯一值可防重复下单 | 传平台的尝试单号 |
| 超时 | 文档要求超时后调用订单详情确认下单结果 | 按"结果未知"处理 |
| 结果回调 | 下单时通过 `url` 传回调地址；需返回字符串 `ok`；失败按 5、10、15、20、25 分钟重试，最多 5 次 | 回调 + 定时查询兜底 |
| 回调签名 | `sha1(time + JSON + apikey)`，JSON 为除 `sign` 外参数排序后编码（`JSON_UNESCAPED_UNICODE`）；**`card_list`、`express_list` 不参与签名** | 回调里的卡密可能被篡改，卡密一律以订单详情接口为准 |
| 订单查询 | 订单详情支持按平台单号或 `external_orderno` 查询，多个用逗号分隔；默认只查近 30 天，`day=0` 查全部 | 查询时传 `day=0` |
| 余额 | `/api/v1/user/info` 返回 `balance` | 余额监控 |
| 商品与成本价 | 商品列表/详情（`goods_price` 为成本价，含状态、库存）、调价记录（最多近 3 天）、商品变更通知（价格、状态、库存变化时推送） | **成本价可以自动同步** |
| 覆盖范围 | 商品只有名称、面值，**没有运营商、省份、快慢充的结构化字段** | 平台本地商品按运营商（以及省份、快慢充）分别建立，映射到范围一致的供应商商品 |
| 手机号归属地 | **没有相关接口** | 不需要：话费按运营商分别建商品，商户自行选择 |
| 下单参数 | 每个商品有下单模板（`attach`），如 `recharge_account` 充值账号；卡密商品不传 | 商品映射中配置"平台参数 → 模板字段"，如手机号 → `recharge_account` |
| 卡密 | 订单详情 `card_list` 明文返回卡号 `card_no`、卡密 `card_password` | 平台取到后加密存储 |
| 购买数量 | 下单传 `quantity`；商品有最小/最大购买数量 | 话费、卡券固定为 1 |
| 撤单 | 撤单接口 + 撤单结果回调（处理中/成功/失败，含退款金额）；商品详情 `can_back` 表示是否支持撤单 | 异常单可由客服发起撤单 |
| 售后 | 售后申请接口（内容、截图、结果回调地址）+ 售后处理回调（处理中/处理完成/终止） | 7.7 售后核实可直接通过接口提交给供应商 |
| 对账 | 无对账文件；订单列表接口可按创建时间、状态分页拉取，每页最多 100 条 | 用订单列表做订单对账 |
| 其他限制 | 商品有可售渠道 `can_buy`、禁售渠道 `can_no_buy`（如抖音）、销售限价 `can_price`、余额限价 `need_balance`（含义文档未说明） | 只在平台后台记录，不展示给商户 |
| 不适用的接口 | "后台接口"需要对方站点管理员账号，"供货接口"用于供货商身份，平台都用不到 | — |

## 2. 订单状态映射

| 卡速售状态 | 含义 | 平台统一结果 | 说明 |
|---|---|---|---|
| 1 | 等待处理 | 处理中 | — |
| 2 | 正在处理 | 处理中 | — |
| 3 | 交易成功 | 成功 | 卡密商品还需拿到 `card_list`，没拿到继续查询 |
| 4 | 取消交易 | 明确失败 | 要求退款金额 `has_back_money` 等于订单金额 `total_price` |
| 5 | 已退款 | 明确失败 | 同上 |
| 4 或 5，且部分退款 | 部分成功 | 结果未知，转人工 | `has_back_money` 小于 `total_price` |
| -1 | 未支付（平台预存款余额不足） | **明确失败**，换下一家供应商，并告警财务及时充值 | 已确认：-1 表示平台在该站点的预存款不足，订单未受理；按"供应商侧问题"处理，同时触发一次该供应商的余额即时查询，避免路由继续把新订单分给它 |
| 3 之后变为 5 | 成功后被退款 | 全额退款：自动按售后核实未到账处理；部分退款：转人工 | 售后、运营商冲正等都可能导致 |

## 3. 错误处理

卡速售只有 200/400/500 三种返回码，400 的 `msg` 是自由文本，**不能根据文案判断是否扣费**：

| 场景 | 处理 |
|---|---|
| 下单返回 200 | 按返回的订单状态映射 |
| 下单返回 400 | 用 `external_orderno` 查订单详情：**查不到订单** → 明确失败，换下一家；**查到** → 按订单状态处理 |
| 下单返回 500、超时、响应无法解析 | 结果未知，按 `external_orderno` 定时查询 |
| 查询返回 400、500 或超时 | 结果未知，继续查询 |
| 400 的 msg 含签名错误、余额不足等 | 照上面规则处理，同时按关键字告警（文案只用于告警分类） |

## 4. 驱动实现要点

- **供应商配置**：接口地址、`UserId`（appid）、`apikey`
- **external_orderno**：平台订单号 + 尝试序号，保证每次尝试唯一
- **下单参数**：按商品映射里配置的模板字段组装 `attach`
- **安全价格**：`safe_price` 传平台售价；供应商成本高于售价时返回 400，按第 3 节查不到订单即明确失败，换下一家
- **数量**：`quantity` 固定为 1
- **回调地址**：`/notify/{供应商编码}`，下单时通过 `url` 传入；验签通过后回复 `ok`
- **回调只作为触发**：收到后调订单详情接口确认状态和卡密，再做扣款、解冻
- **商品同步**：
  - 接收商品变更通知（表单格式，签名只包含 `id` 和 `time`），更新该供应商商品的成本价、状态、库存
  - 商品状态为暂停/禁售或库存为 0 时，路由跳过
  - 每天用商品列表全量校准一次，防止漏收通知
- **查询**：订单详情传 `day=0`；定时查询可批量传多个订单号

## 5. 确认结果

**已确认（2026-09-11）**

| 问题 | 结论 |
|---|---|
| 适用业务线 | 只做话费和卡券，不做电影票 |
| 成功后变为已退款 | 全额退款自动按售后核实未到账处理（订单改已退款、退回商户、返佣作废或扣回）并告警；部分退款转人工 |
| 安全价格 | 下单传平台售价 |
| 购买数量 | 话费、卡券一单一个 |
| 销售限制 | 可售/禁售渠道、销售限价只在平台后台记录，不展示给商户 |
| 手机号归属地 | 不需要；话费按运营商分别建商品，商户自行选择 |
| 状态 -1（未支付） | 平台预存款余额不足，按明确失败处理：换下一家供应商 + 告警财务，同时触发余额即时查询 |
| 测试环境 | 有测试接口，域名等信息待实际配置供应商时录入 |

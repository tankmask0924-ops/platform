# 云洋国内快递 对接说明

> 依据文档：云洋物流 国内快递 API 文档（2026-09-11 整理版）
> 适用业务线：快递
> 对接驱动：云洋

## 1. 核对结果

| 核对项 | 文档结论 | 对平台的影响 |
|---|---|---|
| 接口地址 | 统一入口 `POST /api/wuliu/openService`，用 `serviceCode` 区分接口；工单为 `/api/wuliu/submitWorkOrder` | 供应商配置里填接口地址 |
| 测试环境 | `/api/sandbox/openService`，只用于验证签名，**没有回调推送** | 回调联调要在正式环境下单后取消 |
| 签名 | `sign = md5(appid + requestId + timeStamp + secretKey)`；**请求内容 `content` 不参与签名** | 只能靠 HTTPS 防篡改，驱动只允许 https 地址 |
| 返回格式 | `{code, message, result}`；**code 不统一**：下单、取消、查询、检测渠道等为 `"1"` 成功 / `"0"` 失败，余额、开通渠道、黑名单、工单等为 `"200"` 成功 | 驱动按接口分别判断 |
| 查价 | 检测渠道接口按寄收件地址、重量、体积返回**多个可用渠道**；每个渠道有运费、保价费、耗材费、总费用、官方原价、计费规则、是否支持保价、预约时间段（菜鸟必传） | 平台查价返回可选快递公司列表，**全部开放**给商户；商户可传保价金额 |
| 报价有效期 | 没有报价单号和有效期 | 下单时重新检测渠道拿价格 |
| 下单 | 传渠道 ID 下单，同步返回运单号 `waybill`、商家单号 `shopbill`、冻结运费 `freight`（`feeOver=0`）；个别快递运单号异步获取 | 以 `shopbill` 作为供应商订单号 |
| 防重复 | **没有防重复的订单号参数**；可传 `extendField1~3` 自定义字段，回调时原样返回 | 超时不能重试，见第 3 节 |
| 取消 | 只有待揽收状态可取消；德邦重货等部分渠道不支持接口取消 | 揽收后取消直接返回失败原因 |
| 状态 | `typeCode`：1 待揽收、2 运输中、3 已签收、4 拒收退回、99 已取消 | 见第 2 节 |
| 计费 | `feeOver`：0 冻结、1 已扣费；`totalFreight` = 运费 + 保价费 + 耗材费 + 逆向费；**扣费后签收环节仍可能产生耗材费、保价费**；拒收退回、换单会产生逆向费 | 以 `feeOver=1` 为结算点，之后的变化按费用调整处理；订单完成时间用签收合理 |
| 回调 | 状态、重量变化时推送；回调地址在云洋个人中心配置（账户级）；成功需返回 `{"code":1,"message":"推送成功"}`；**回调没有签名**；文档未说明重试机制 | 回调不可信，见第 3 节 |
| 查询 | 订单详情、轨迹查询，都按运单号或商家单号 | 定时查询兜底 |
| 余额 | `yue` 总额、`keyong` 可用、`dongjie` 冻结 | 余额监控取 `keyong` |
| **供应商返佣** | **文档中没有任何返佣字段** | 快递暂按无返佣开发，不给商户返佣，待云洋确认 |
| 售后 | 工单提交（1 重量核实、2 物品理赔、6 取消订单、11 现结到付、8 催取件、9 催物流、10 催派送）、工单回复、工单回调（含重量赔付金额、理赔金额、状态异常处理结果） | 不对商户开放，客服代提交；重量核实退回的运费按费用调整退给商户；理赔款客服核实后调账 |
| 对账 | 没有对账文件，也没有订单列表接口 | 只能按平台订单逐笔查询订单详情核对 |
| 其他接口 | 查询开通渠道（成本价表、省份开通状态）、原价查询、黑名单查询/添加、德邦筛单、得物收件地址、面单打印（PDF） | 暂不使用；不提供面单打印 |

## 2. 云洋状态与平台订单的对应

| 云洋 | 平台处理 |
|---|---|
| 下单成功（`feeOver=0`） | 订单处理中；以返回的冻结运费重新计算预估售价，调整冻结金额 |
| `feeOver` 变为 1 | 按 `totalFreight` 结算，多退少补；订单**成功** |
| 扣费后 `totalFreight` 变化 | 费用调整：补扣或退回，回调商户 |
| `typeCode=3` 已签收 | 记录订单完成时间，开始计算返佣期限 |
| `typeCode=4` 拒收退回 | 逆向费按费用调整补扣；完成时间按兜底天数 |
| `typeCode=99` 已取消（未扣费） | 订单取消，全额解冻 |
| 扣费后退回运费（重量核实、状态异常工单通过） | 按费用调整退回商户 |

## 3. 风险与对策

| 风险 | 后果 | 对策 |
|---|---|---|
| **回调没有签名** | 伪造"已取消"回调骗平台解冻，或伪造低运费 | 回调只作为触发：收到后调订单详情接口（带签名的请求）拿最新数据再处理；回调地址带随机令牌；**不做回调来源 IP 白名单**（已确认），回调失败由云洋自动重试 |
| **下单没有防重复单号** | 超时重试会重复下单、重复冻结供应商和商户的钱 | 下单超时**不重试**，订单标为结果未知；`extendField1` 传平台订单号，后续回调带回时自动关联；超过异常单时长仍无回调，转人工在云洋后台核实 |
| 请求内容不参与签名 | 请求被篡改 | 只走 HTTPS |
| 查价和下单时价格可能不同 | 冻结金额不准 | 下单前重新检测渠道；以下单返回的冻结运费为准调整冻结金额，可用余额不足时差额留到结算时补扣 |
| 测试环境没有回调 | 联调困难 | 回调在正式环境小额下单后取消来测试 |

## 4. 驱动实现要点

- **供应商配置**：接口地址、`appid`、`secretKey`；云洋后台回调地址配置为 `/notify/{供应商编码}?token=...`
- **请求**：每次生成新的 `requestId`（UUID）
- **渠道**：`channelTag` 传"智能"（得物、重货暂不开放）；菜鸟渠道必须传预约取件时间
- **对商户隐藏渠道 ID**：查价结果中云洋 `channelId` 换成平台自己的渠道编号或临时报价编号，下单时再换回
- **下单**：`weight` 为整数（公斤）；`extendField1` 传平台订单号
- **加价**：只对运费 `freight` 加价；保价费 `freightInsured`、耗材费 `freightHaocai`、逆向费 `changeBillFreight` 按成本
- **保价**：商户传保价金额时传 `insured`，只有 `allowInsured=1` 的渠道可选
- **结算依据**：订单详情中的 `feeOver`、`typeCode`、`totalFreight`、`freight`、`freightInsured`、`freightHaocai`、`changeBillFreight`

## 5. 确认结果

**已确认（2026-09-11）**

| 问题 | 结论 |
|---|---|
| 快递返佣 | 文档无返佣字段，暂按无返佣开发，快递不给商户返佣，待云洋确认 |
| 加价范围 | 只加在运费上，保价费、耗材费、逆向费按成本转给商户 |
| 快递售后 | 不对商户开放，商户找平台客服，客服代提交工单；重量核实退回的运费按费用调整退给商户 |
| 理赔款 | 客服核实实际赔付后调账加到商户余额 |
| 可选快递公司 | 全部开放给商户 |
| 保价 | 开放，保价费按成本 |
| 面单打印 | 不提供 |
| 回调来源 IP | 不做限制，靠随机令牌 + 查询接口兜底 |
| 回调重试 | 云洋回调失败会自动重试（已确认，具体次数间隔待实际对接时观察） |
